Build & publish a tool

A tool is a folder: a manifest, a Python or R file and the pixi environment it runs in. Write it with the SDK, check it with the gates and publish it by pull request to the public registry.

Read the author guide How tools work · Docs

The author’s loop

new → validate → pack → pull request

The commands are the SDK’s: python -m pointillviz_tool. The gates run on your computer, again in the registry and once more on install.

  1. Start from the scaffold

    new writes a starter tool in Python, or in R with --r, that passes every gate once its environment is locked.

  2. Write run(ds, params)

    Read the dataset through ds, and return the outputs the manifest declares.

  3. Declare the manifest

    Each typed parameter becomes a control; requirements decide which datasets offer the tool, and gpu says whether it can use a GPU.

  4. Lock the environment

    pixi.toml lists what the tool needs, and pixi lock pins it for every platform in pixi.lock.

  5. Validate

    validate builds the environment, runs the gates and names the one that failed.

    The gates

  6. Pack

    pack writes a .pvtool bundle, to try in PointillViz with Install from file.

  7. Publish

    Open a pull request that adds the tool’s folder to the public registry. The registry runs the gates in the tool’s own environment; once the request is merged, the tool is released and listed here.

    The gates, again

  8. Install

    PointillViz builds the tool’s environment and runs the gates once more before it installs.

    The gates, once more

The public registry

Every published tool is a folder there: its code, manifest, environment and README. Read a tool before you install it, or start yours from one.

The gates

What each gate checks, in the order they run. Every run uses the CPU, so a tool meant for a GPU must also run without one.

#GateWhat it checks
1bundleThe bundle’s layout, size and file types.
2manifestEvery field of plugin.json, defaults included.
3environmentpixi.lock matches pixi.toml, which declares python, numpy and scipy, and for R also r-base and r-jsonlite.
4entrytool.py or tool.R loads in the tool’s environment and defines run(ds, params).
5imports advisoryReports network, subprocess, file-write, dynamic-code and environment use, with file and line. Advisory: it never blocks.
6fixtureRuns on a synthetic dataset at its own defaults.
7resultReturns the declared outputs and no others, each with values to draw.
8edgeRuns with every parameter at its minimum, then at its maximum, without crashing.
9no_mutationWrites nothing into the dataset.
